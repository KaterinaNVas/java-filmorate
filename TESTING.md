# Тестирование валидации Filmorate

Запуск из корня проекта на JDK 21:

```shell
mvn test
```

Добавлены три класса в src/test/java/ru/yandex/practicum/filmorate/controller:

- FilmControllerTest — проверки создания и обновления: пустое название, отсутствие даты, даты 27/28/29 декабря 1895, отсутствующая/нулевая/отрицательная длительность, минимальная положительная длительность, описание 199/200/201 символ, пустое и отсутствующее описание.
- UserControllerTest — пустой email и email без @, пустой логин и логин с пробелом, отсутствующая дата рождения, вчера/сегодня/завтра, подстановка логина при пустом имени.
- EmptyRequestTest — HTTP 400 для POST/PUT /films и /users без тела и с JSON null; хранилища остаются пустыми.

Unit-тесты проверяют валидацию через контроллеры: в текущем проекте правила реализованы именно там, модели не содержат аннотаций валидации. MockMvc используется без запуска сервера. Существующий contextLoads сохранён.

Отклонённое обновление дополнительно проверяется на сохранность исходных данных. Проверяются отсутствие id и неизвестный id при обновлении.

Исправления в UserController:
- Отсутствие birthday вызывает ValidationException вместо NullPointerException (при создании и обновлении).
- Дата сравнивается с LocalDate.now() на момент запроса вместо статического TODAY.

Генерация id, модели и pom.xml сохранены. Формат длительности Duration не изменён.

Текущая проверка email требует наличия @; усиление формата email в эту задачу не включено. Исключения приложения не имеют HTTP-обработчика; тесты HTTP 400 относятся к отсутствию тела и JSON null, которые отклоняет Spring.

Проверка в среде подготовки: 77 тестов, 0 ошибок, 0 падений. Установлена JDK 17; версия переопределена только аргументом запуска, pom.xml оставлен с JDK 21. Из-за запрета динамического подключения Mockito использован явный агент:

```shell
mvn -Djava.version=17 -DargLine=-javaagent:/path/to/mockito-core-5.17.0.jar test
```

На локальной JDK 21 сначала используйте обычную команду mvn test.
